版本：`2.3`

适用范围：当前本地开发版与 macOS arm64 桌面测试版。程序只在玩家电脑上运行，剧情、人物、原文、存档和 API 配置不会上传到项目运营服务器；生成剧情时，本轮选中的必要资料会发送给玩家选择的模型供应商接口；使用“AI 原文分析与生成”时，所选原文或代表片段会在两个阶段分别发送给该供应商。

## 一、第一次启动

### 最简单的启动方式

桌面测试版：打开 DMG，把其中整个 `AI酒馆` 文件夹复制到“应用程序”或个人目录等可写位置，再双击文件夹中的 `AI酒馆.app`。必须保留同级 `用户数据`，不要直接从只读 DMG 运行，也不要只复制 `.app`。首次打开临时签名开发包时，macOS 可能要求在“系统设置 → 隐私与安全性”中确认。

源码开发版：在 macOS Finder 中双击项目根目录的 `启动AI酒馆.command`。启动器会检查环境、安装缺少的依赖、打开开发服务器并启动浏览器。

### 终端启动（开发阶段）

也可以在项目目录中运行：

```bash
npm run dev
```

默认地址为：

```text
http://127.0.0.1:3210
```

源码开发版会在项目的 `data/` 目录建立 SQLite。桌面版会在 `.app` 同级 `用户数据/数据/` 建立 SQLite，并把模型配置、缓存和日志也放在 `用户数据/`。两种模式的数据不会进入 Git 或新生成的安装包。

### 启动后先检查什么

启动后首先进入主菜单，应显示：

- 本地数据库已连接；
- 当前模型供应商是否已配置；
- “新剧本”“继续游戏”“API 配置”和“退出”四个入口。

“新剧本”和“继续游戏”会分别进入二级页面；“API 配置”会在主菜单上打开本机配置窗口；桌面版点击“退出”会正常结束程序，网页开发版需要关闭浏览器页面。

源码开发版若页面无法打开，先确认终端中的开发服务器仍在运行，并检查端口 `3210` 是否被占用。桌面版使用随机本地端口；启动失败时查看 `用户数据/日志/桌面端.log` 和 `用户数据/日志/本地服务.log`。

## 二、配置模型供应商

主菜单底部显示当前供应商和模型。点击“API 配置”，可以选择：

- **DeepSeek**：继续使用已有 DeepSeek 地址、模型和密钥；
- **OpenCode Go**：自动使用套餐 API 地址，可读取该套餐当前暴露的模型；
- **OpenAI 兼容云端服务**：填写服务商提供的 Base URL、模型名称与 API Key；
- **本地 OpenAI 兼容服务**：连接本机运行的兼容接口，API Key 可以留空。

设置页顶部的“已配置 API”摘要会直接显示当前 API 名称、类型、模型、鉴权状态和 Base URL，不需要进入表单逐项查找。点击“删除已配置 API”并确认后，程序只会清除本机保存的供应商、地址、模型、输出方式和密钥；剧本、游戏存档、数据库备份以及此前导出的模型目录 JSON 都不会删除。

推荐的操作顺序：

1. 选择供应商类型；
2. 填写 Base URL 和 API Key；
3. 同一供应商下 API Key 留空会继续使用已保存密钥；切换供应商时必须重新填写，避免把旧密钥发送给新地址；
4. 点击“读取模型”，从 `/models` 自动取得列表；也可以手工填写准确的模型 ID；
5. 在列表选择模型。绿色“协议可兼容”只表示接口形状匹配，黄色“需要审核”表示目录没有给出协议，灰红色“协议暂不支持”不能选择；审核成功的当前模型会改为“已审核可用”；
6. 点击“审核可用性”，确认配置、目录、所选模型、token 生成权限和 JSON 输出均通过；
7. 点击“保存并使用”。配置会立即对当前进程生效。

读取目录通常不使用生成额度；完整审核会发送一次最多 64 token 的最小 JSON 请求。某个模型能出现在目录里，不代表当前 token 一定可以生成。OpenCode Go 套餐同时包含多种 API 协议，当前酒馆只支持 Chat Completions；Messages 和 Responses 模型会显示在清单中，但不会发起无效审核。

读取后可以点击“导出 JSON”，保存 `ai_tavern_model_catalog_v1` 清单。文件包含模型 ID、协议分类和当前所选模型的审核结果，不包含 API Key。它适合记录和比较套餐模型，不会自动变成运行配置；以后使用时仍应重新审核。

如果兼容服务报告不支持 `response_format`，把“JSON 输出方式”改为“仅用提示词要求 JSON”。本地服务可使用 `http://127.0.0.1` 或 `http://localhost`，远程服务必须使用 HTTPS。

源码开发版配置保存在项目根目录 `.env.local`；桌面版保存在软件文件夹内的 `用户数据/配置/模型.env`。两者格式相同，也可以在程序退出后手工编辑：

```dotenv
AI_PROVIDER=deepseek
AI_API_BASE_URL=https://api.deepseek.com
AI_API_KEY=填写你的DeepSeek密钥
AI_MODEL=deepseek-v4-flash
AI_JSON_MODE=response_format
```

注意：

- 不要给变量名添加 `NEXT_PUBLIC_`；
- 只有手工修改文件后才需要重新启动程序；
- API Key 只用于本地服务端向供应商鉴权；
- 页面和上下文快照都不会返回 API Key；
- 新生成的桌面安装包不包含任何已经配置的 API Key、开发数据库或测试剧本；
- 旧配置没有 `AI_PROVIDER` 时仍按 DeepSeek 读取；
- 切换模型只影响后续请求，不会改写既有剧情或上下文快照。

## 三、首页与已有剧本

主菜单提供四个主要选项：

- **新剧本**：进入资料准备与第一幕编辑页面；
- **继续游戏**：进入本地档案页面，显示已有剧本、完整存档和整库备份；
- **API 配置**：查看、审核、切换或删除本机保存的模型连接；
- **退出**：结束桌面程序。网页开发模式受浏览器限制，会提示玩家关闭当前页面。

两个二级页面都可以点击“返回主菜单”。新剧本创建成功后不再返回档案列表，而是直接进入游戏内的第一幕。

### 打开剧本

在已有剧本列表中点击继续，即可恢复该剧本当前活动分支、人物状态、地点、世界书、剧情任务和最近回合。

继续游戏页面的“导入游戏存档”可以直接选择 AI 酒馆导出的完整存档 JSON。程序先校验文件版本、摘要、内部引用和完整性，再询问是否导入；成功后建立名称带“（导入）”的隔离副本并直接进入游戏，不覆盖本机已有剧本。单文件最大 100 MB。

### 修改名称

重命名只改变剧本和会话的显示名称，不会创建新回合，也不会修改角色、世界书或剧情状态。

### 删除剧本

删除会永久清理这个本地剧本的全部分支、回合、人物状态、世界书变化、原文、记忆和存档。只有此前导出的完整存档或整库备份可以恢复。页面会先显示确认提示。

### 导出

已有剧本旁的导出按钮会生成完整运行存档，适合迁移已经游玩的故事。它与“开局剧本包”不同：完整存档包含动态状态和历史回合，开局剧本包只描述尚未游玩的第一幕。

## 四、新建剧本

新建剧本需要填写：

1. 剧本名称与世界观；
2. 玩家控制角色；
3. 主要 AI 角色；
4. 可选的其他 AI 角色；
5. 开场地点与开场正文；
6. 初始剧情走向。

### 玩家角色

玩家角色由玩家控制。设定应描述身份、能力、背景和已知事实，不要预先写死玩家会说什么、做什么、同意什么或爱上谁。

### 主要角色和其他角色

AI 角色的资料应包含：

- 身份与当前处境；
- 稳定性格、价值判断和行为边界；
- 说话方式；
- 与玩家及其他角色的初始关系；
- 可选的开场消息和对话示例。

其他角色可以设置是否在第一幕现场。不在场角色仍保留卡片，但不会无理由参与当前场景。

### 开场正文

开场场景是玩家进入游戏后直接阅读的剧情，不是提示词。应写清时间、地点、在场人物、可观察冲突，并在适合玩家回应的位置结束。

### 初始剧情走向

剧情走向是故事外的导演目标，NPC 不会知道。它会持续影响后续回合，直到剧情以真实事件和对话证据完成该目标，之后系统可以接续预埋任务或生成新的自然目标。

## 五、导入人物卡、世界书和剧本包

新建页面的“导入或生成剧本资料”支持：

- Character Card V2/V3 JSON；
- 旧版扁平人物卡 JSON；
- AI 酒馆世界书和常见 SillyTavern World Info JSON；
- AI 酒馆完整开局剧本包 JSON。
- UTF-8 TXT/Markdown 原文自动生成剧本包。

### 推荐流程

1. 选择文件；
2. 阅读格式识别结果、警告和预览；
3. 确认人物分工与世界书条目数；
4. 在开局表单中继续修改；
5. 点击创建剧本后才正式写入数据库。

普通 JSON 导入预览不会调用 AI 模型，也不会消耗 API 额度。文件解析或任何数据库写入失败时，不会留下半个剧本。

### AI 原文分析与生成

已经配置可用模型后，点击“上传原文，先确认分工”，选择 `.txt` 或 `.md` 原文。文件至少 200 字符、最多 900,000 字符且不超过 3.5 MB。程序分两个阶段工作：

1. **原文分析**：识别 2～20 名重要人物，说明各自作为玩家角色或主要 AI 角色的适合程度，并给出 1～5 个开场候选。此阶段不会修改当前表单。
2. **玩家确认**：从下拉框选择玩家控制角色和主要 AI 角色，两者不能相同；再选择带章节、地点、摘要和在场人物的第一幕候选。
3. **正式生成**：点击“按当前选择生成剧本包”。程序再次调用模型，强制采用所选人物姓名和开场章节，再生成世界书、人物卡、任务链和开场正文。
4. **自动填入**：只有最终标准包通过完整校验后，才替换下方表单。
5. **按分区修改**：在“只重新生成一个部分”中选择角色资料、世界书、剧情任务或开篇，填写不满意原因，再点击对应重做按钮。
6. **比较并确认**：新版本通过整包校验后，页面按项目并排显示“当前表单”和“AI 新版本”，并标注新增、移除或修改。此时还没有覆盖表单。
7. **采用或放弃**：点击“采用新版本”才更新目标分区和下载基线；点击“放弃新版本”则保留全部当前内容和修改意见。

- 原文不超过 48,000 字符时，完整正文会发送给当前模型供应商；更长时只发送覆盖开篇、中段和结尾的代表片段。
- 完整原文由本地程序原样放入生成包的原文参考，不依赖模型复写。
- 分析和正式生成分别调用模型，每个阶段结构不合法时最多再调用一次修复；完整流程通常 2 次、最多 4 次请求。
- 正式生成会核对模型返回的玩家角色、主要 AI 角色和开场章节；模型擅自换人或换章节时不会直接填表。
- 成功后仍应检查人物性格、开场阵容、世界书和首个任务。所有字段都可编辑。
- 分区重做的修改意见必填，最多 2,000 字符。每次都会再次调用当前模型，并可能额外调用一次修复，因此会消耗新的 API 额度。
- 采用分区重做结果后只更新所选字段：角色会更新三类人物资料，剧情任务会同步首个任务和初始目标，开篇不会替换已有任务链。未选中分区的手工表单编辑会保留。
- 如果在等待生成或查看差异时又修改了同一目标分区，程序会阻止采用，要求放弃后重新生成，避免覆盖没有出现在预览中的编辑。
- “下载生成包”保存最近一次通过校验的生成基线，包含已经成功的分区重做；下载后继续手工修改网页表单仍不会同步改写这份 JSON，需要以最终创建的本地剧本为准。
- 请求、解析或校验失败时，当前未保存表单不会被替换，也不会写入数据库。

### 完整剧本包

完整包可以一次载入：

- 玩家卡；
- 主要角色和其他角色卡；
- 世界书；
- 原文参考；
- 剧情任务链；
- 伏笔与偏离触发器；
- 人物初始状态（受伤、中毒、增益等，角色未察觉的暗伤/毒会标记为隐藏，需剧情探索发现）；
- 初始关系、开场地点、场景和初始目标。

导入后仍应检查开场人物、原文进度和当前任务是否正确；伏笔与触发器会随“建立世界”物化为游戏内实体，可从工作台的“伏笔”“触发器”栏目查看；人物初始状态会物化为角色的状态词条，可在人物管理中查看。

## 六、游戏页面

游戏页面主要分为正文区、玩家回应区、剧情走向区、本轮变化区和右侧状态栏。正文列从上到下依次为：当前剧情与对话、原文参考、玩家回应、剧情走向、本轮变化。页面顶部显示世界名称与当前游戏内日期（“游戏内第 N 日”）。游戏内日期只由剧情推进驱动：只有剧情中实际经过数小时、次日或数日后才会推进，普通对话回合不会凭空增加天数。

### 正文区

显示当前或历史回合的：

- 场景叙述；
- 角色对话；
- 本轮引用的原文片段。

正文区底部另有折叠的“内心活动”分区，展示本轮有内心独白的 AI 角色想法（角色之间互相不知道，玩家角色也不知道；想法的内容只用于塑造该角色后续行动，不会自动成为台词或动作）。历史回合回看同样可见。

“玩家回应”紧接在正文之后，便于频繁选择候选项、填写自定义决定和角色言行；“生成下一回合”按钮也放在这个区域底部。生成过程中会显示进度条与已生成字数，并可以随时点击“中断”停止本次生成（输入保留，可修改后重新生成）；若生成已在中断前完成，页面会提示并展示最新回合。与上一回合高度重复的续写会被系统判定并自动要求推进重写。“剧情走向”是单独的导演输入区，位于玩家回应下方；它通常不需要每轮修改。“本轮变化”排在这两个区域之后，用于按需查看状态变化、token 用量和 AI 实际上下文。“本轮变化”中的“模型提示”会展示一致性提醒（例如正文提到某角色的状态但词条未同步更新），提示内容不影响剧情结果，仅供核对。

### 顶栏操作

- **主菜单与生成模型**：顶栏左侧返回主菜单，并可在保存了多套 API 配置时直接切换当前使用的模型；
- **人物与地点**：顶栏中部“人物”“地点”按钮直达剧本工作台对应栏目。“地点”栏目即地图：列出全部已记录地点（含剧本包预注册的地点），每个地点显示描述与当前位于该地的人物；位置未知或尚未登场的人物不会显示。当前所在处标注“当前位置”，重要地点标注“重要”；
- **编辑剧本与分支存档**：分别打开剧本工作台和分支与存档面板。

### 右侧状态栏

显示：

- 当前分支与恢复点数量；
- 回合记录；
- 当前地点；
- 在场人物；
- 原文资料状态；
- 生效世界书；
- 长期记忆；
- 修改记录与恢复；
- 当前剧情走向和任务链。

状态栏独立滚动，正文不会因为右侧内容较长而产生大段空白。

### 编辑剧本总入口

页面顶部的“编辑剧本”打开统一剧本工作台。右侧各资料区的管理按钮也会进入同一工作台，并自动选择对应栏目。

## 七、候选选项与三种输入

### 候选选项

当对面角色提出交易、要求、威胁或条件时，系统通常提供：

- 接受；
- 部分接受；
- 拒绝。

当剧情询问玩家下一步怎么做时，系统通常从以下角度给出不同方案：

- 善意；
- 中立；
- 利己或邪恶。

候选项只是建议。玩家可以不用候选项，改用自定义输入。

当剧情明显偏离剧本路线后，选项会自然呈现两条出路：承受代价、押上一切的决断，以及绕过原作路径、用当前积累的关系与资源达成目标的另类方案——它们都以正常剧情措辞出现，不会直接点明"坏结局"或"跳过原作"。剧情不会因为偏离而一直原地打转，每个选项都会推动局势发生变化。

### 输入一：自定义选项

用于代替候选项，表达玩家本轮选择。例如：“表面接受条件，但要求对方先交出一半证据。”

### 输入一：回合模式（场景）

生成新回合前（剧情驱动时间模式下）可以选择回合模式：

- **标准生成**（默认）：正常生成下一回合；
- **详细描写场景**：时间保持不变，由 AI 详细展开你提供的场景（环境、人物、氛围、细节）；
- **场景推进**：时间按剧情推进，由 AI 根据你提供的场景描写接下来要发生的事。

选择后两种模式时需填写"场景"内容（最多 2000 字），可与角色言行、想法、剧情走向同时使用（场景为主要内容来源）。五回合一天模式下不提供此切换。

### 输入二：角色想法

用于填写玩家角色当前的内心想法（限长 1000 字）。想法是玩家角色自己的心理活动，**其他角色不会知道**，也不会直接成为玩家角色说出口的话或做出的动作；但它会影响玩家角色后续的言行风格、可选行动倾向与故事走向（模型会以想法作为角色的内在动机）。想法需要与角色言行或选择一同提交才会生效。

### 输入三：角色言行

用于填写玩家角色在故事中说的话或做的动作。可以选择：

- 说话；
- 动作；
- 说话与动作。

这些内容会被其他角色观察到并产生剧情后果。

### 输入三：剧情走向

用于表达故事外的长期意图。例如：“让双方在共同调查三次事件后逐渐建立信任。”

剧情走向使用玩家回应下方的独立输入区。它不会直接成为角色知道的事实，也不会要求本轮立即完成。通常只在希望改变后续长期发展时填写或修改；玩家可以修改或清空它，手工输入优先于系统自动接续的目标。

### 提交

选择候选项或填写任意玩家输入后，玩家回应区域底部的“生成下一回合”按钮启用。模型返回的 JSON 只有通过角色 ID、事件证据、地点、候选项和状态变化校验后才会整体保存。

### 属性判定与骰子

当剧情出现有明显成败可能的关键行动（撬锁、潜行、说服、搜索、战斗动作等）时，生成结果会包含属性判定请求，但**不会立即保存本轮**：界面弹出“属性 vs 难度 + 骰子”面板，列出每项判定的角色、属性值、难度和判定缘由。

- 属性包括力量、敏捷、感知、意志、魅力、智力、体质（0-100，未设定时按 50 计），数值随剧情变化。
- 点击“掷骰”生成 1-100 的骰子点数（可重掷），页面即时预览判定倾向；
- 点击“确认判定”后，系统确定性结算并把结果作为已发生事实回填该回合：|属性−难度| ≥ 30 时实力悬殊直接判定，无需掷骰；否则按“属性 + 骰子 × 30%”与难度比较，达到难度为成功、差 10 点以内为部分成功、否则失败。
- 结算结果会追加为本回合的事实事件与叙述消息，判定记录可在“修改记录”审计和该回合历史中查看。
- 也可以选择“跳过本轮判定”（记为放弃判定），回合仍会正常提交。

### 结局警示

当剧本中的偏离触发器把剧情推向坏结局（`bad_end` 标志置位）时，游戏正文上方会显示红色“结局警示”横幅，说明把局势推向坏结局方向的后果。之后的选择将决定最终结果，警告不会自动消失。横幅同时提供“回到结局前”入口，可以从最近的恢复点恢复剧情重新选择路线（见“结局后回到结局前”）。

## 八、重新生成

最新 AI 回合顶部提供“不满意，重新生成”。

### 操作方法

1. 点击重新生成；
2. 选择重写模式：**标准重写**或**日期修正**（正文暗示时间流逝——次日、数日后等——但游戏内日期未推进时使用）；
3. 填写具体原因（日期修正模式下可以留空，仅修正时间推进；也可以补充其他希望调整的细节）；
4. 说明希望修改的情节、AI 控制角色或 NPC 的动作、台词、反应、叙述风格或候选项；
5. 确认后再次调用当前 AI 模型。

日期修正模式会专门核对正文时间描写与游戏内日期：正文确实暗示时间流逝时，重写结果必须正确声明结束日期并与正文自洽；正文没有时间流逝时保持日期不变，不会虚构时间流逝。五回合一天模式下日期由回合固定推进，该模式会提示通过继续推进回合实现日期变化。

系统会从上一回合结束状态重新推演，沿用玩家当时的选择、言行和剧情走向，不会把不满意的旧版内容当成已经发生的事实。

可以直接要求调整、删除、替换或重排本轮中由 AI 控制角色和 NPC 作出的动作、台词、态度、事件顺序、场景结果与状态变化，例如“不要让她离场，改为留下盘问玩家”。旧版最新回合只是待替换草稿，不属于必须保留的既定事实；模型不能以“不能控制他人”或“动作已经发生”为由拒绝。原玩家输入和更早剧情仍保持不变，模型也不能替玩家角色补做未授权行为。

成功后：

- 回合 ID 和序号不变；
- 当前回合的叙述、对话、事件、状态变化和实际上下文整体替换；
- 旧版结构化内容和修改意见留在本地重生成记录中。

以下情况会阻止重新生成：

- 当前查看的不是最新回合；
- 回合属于父分支继承的分支起点；
- 该回合之后已经手工修改人物、地点、任务、世界书、原文、记忆或执行状态回滚；
- 分支在请求过程中已继续前进。

## 九、剧本工作台

工作台统一包含“人物、地点、剧情任务、伏笔、触发器、世界书、原文、记忆、修改记录”九个栏目。栏目切换不会创建剧情回合，也不会调用 AI 模型；保存后的内容从下一次生成开始生效。前八个栏目的保存请求使用同一套本地内容协议，成功后会一起刷新剧本、原文目录和记忆；网络中断后重试不会重复执行同一操作。“修改记录”集中显示原文、记忆与持久状态的历史。

### 9.1 人物

支持：

- 新增 AI 角色；
- 修改姓名、身份、性格和第一句话；
- 暂时离场或重新登场；
- 设置或解除“行动受限”（死亡、被关押、被控制、被束缚或其他原因）；
- 查看、添加或移除角色的状态词条（受伤、中毒、增益等 buff/debuff）；
- 停用或重新启用角色。

暂时离场保留角色卡，只修改当前在场状态。停用会使该角色不再进入可用人物列表和后续模型扮演范围。过去剧情不会被改写。

**行动受限**：角色死亡、被关押、被控制或受束缚后，可在人物管理中为其设置“行动受限”及原因（人物列表会显示受限标记）。受限期间模型不能替该角色说话、安排其登场、移动或发起属性判定；解除必须由剧情真实事件触发（复活、越狱、挣脱控制等），也可以在人物管理中直接解除。已设定受限的角色保留在剧情叙述与人物列表中，只是不再自由行动。

**状态词条**：角色的 buff/debuff（受伤、中毒、增益等）会作为词条记录在人物管理中（增益/减益区分显示，带到期日）。角色未察觉的隐藏状态（暗伤、被下毒、血脉异常）不会出现在角色可见信息中，需要通过剧情探索（检查伤口、求医、观察症状等）认识到后才会解锁显示。状态词条随剧情增减或恶化恢复；角色身上存在负面状态且有解决办法时，角色的行动与选项会倾向处理它（求医、解毒、治疗、休息等）。剧本包导入的人物初始状态会物化为开局词条。

人物管理顶部同时展示“角色关系”面板：按角色对列出信任、好感、恐惧、敌意与敬意（-100 ~ 100）的当前数值、关系描述与**关系类型**（家人、情侣、朋友、对手、同侪、同盟、泛泛之交等）。每对关系都可以点击“编辑关系”手动修改：调整五维度数值（-100 ~ 100）、选择关系类型、改写关系描述；默认只修改一个方向（双向记录独立演化），勾选“同步反向数值”可把改动一并应用到反向记录。手动修改会进入“修改记录与恢复”，可以回看和撤销。关系类型会随剧情定性变化（如发现并无血缘后姐弟转为朋友、再发展为情侣），转化记录在“修改记录”中可回看（“关系类型 家人 → 情侣”及原因）。关系加深会按具体维度分别记录——信任（托付秘密、可靠守约）与好感（心动、亲近、思念）是不同的维度，尤其是情侣或互有好感的关系深化时会区分到底加深的是哪一边，并在修改记录中指向对应的剧情事件。剧本包声明的初始关系会自动建立双向记录（如“李长安 ↔ 林听雪”）；数值会随剧情中的关系变化实时更新。

**角色已知信息**：角色在剧情中获知的重要信息（对话告知、信件、发现、偷听等）会被登记为该角色“已知信息”，并按角色隔离（一个角色知道不等于其他角色也知道）。已登记的信息在后续剧情中不会重复出现“首次获知”的表述，剧本推进到相关情节时会体现该角色已掌握信息并据此行动。人物管理中可查看各角色的已知信息清单。

**次要人物名录**：剧情中随口提到的没有人物卡的背景 NPC（亲人、邻居、路人等）会被自动登记进“次要人物名录”，记录其名字、与在场角色的关系和简要描述。名录的作用是防止长剧情后期 NPC 名字漂移——已经登记的角色再次出场时，AI 必须沿用原名；名录只作上下文引用，不会进入可扮演角色列表。

### 9.2 地点

支持：

- 新增和编辑地点名称、描述；
- 配置移动到此处时默认登场的 AI 人物；
- 把当前位置移动到已有地点；
- 停用或重新启用非当前地点。

手工移动时，玩家角色始终随行；地点默认人物登场，其他人物离场。剧情生成也能依据真实事件发现新地点并自动同步阵容。剧本包可以预注册全部可能出现的地点，开局即进入地点清单（地点栏目）；不在场角色也可以随剧情显式移动位置（如返回宅邸、前往城外），之后可从正确位置重新登场。

### 9.3 剧情任务

支持建立最多 30 个任务，并设置：

- 稳定任务 ID；
- 标题和目标；
- 完成条件；
- 启用条件；
- 前置任务；
- 连续性说明；
- 是否允许自动接续；
- 游戏内期限（第 N 天前完成）。

系统会阻止重复 ID、不存在的前置任务和循环依赖。当前任务不能暂停；已完成、已偏离或**已过期**任务作为剧情历史锁定（过期任务不能再编辑或切换）。设有期限的任务在剧情时间推进到期后，系统会把它标记为"已过期"并退出当前任务链，同时后续回合会在剧情中强制显现期限后果（如中毒数日未治而恶化、约期已过、反派抢先），不能假装时间没有流逝；玩家仍可通过剧情完成目标或改变局势。

### 9.4 伏笔

剧本包可以预埋跨章节伏笔（最多 30 条）。每条包含：

- 稳定 ID 与关键词（相关时刻把伏笔带进上下文）；
- 出现条件（满足后伏笔悄然埋入剧情，NPC 不应察觉其目的）；
- 回收条件与回收概要（剧情自然抵达回收条件时，模型必须呈现概要中的核心信息）；
- 相关角色（可选）。

伏笔与剧情任务互补：任务关心“下一步要做什么”，伏笔保证“很久以前的暗示在关键时被回收”，避免短上下文下伏笔真正目的丢失。尚未回收的伏笔可以编辑或删除；已回收的伏笔作为剧情历史锁定。

### 9.5 偏离触发器

剧本包可以预埋“偏离主线就会招致后果”的意外阻碍（最多 30 条）。每条包含触发条件、后果描述，可选：

- 状态影响：按角色名调整关系值（信任/好感/恐惧/敌意/敬意）、直接设定角色属性（0-100，白名单属性）、或置位 `bad_end` 标志（游戏页显示结局警示横幅）；
- 期限（第 N 天前必须生效，超过后系统强制触发）。

条件满足时，后果会真实写入本轮剧情（不会因后果严厉而回避），系统同时强制应用声明的状态影响。已触发的触发器作为剧情历史锁定。示例：主角弱小时强闯反派地盘 → 强大反派提前登场；已婚状态下与异性接触 → 正主怀疑、敌我关系大幅转变。

### 9.6 世界书

世界书栏目集中展示内置基础层、导入基础层、剧情动态层、玩家新增层和玩家修订层。可以：

- 按名称、触发词或正文搜索，并按层级筛选；
- 新增长期世界事实；
- 编辑名称、主要与次要触发词、正文、常驻状态、选择性匹配、注入位置、排序、概率和扫描深度；
- 停用、重新启用或软删除条目；
- 展开玩家修订层，逐字段比较基础值与当前值；
- 撤销覆盖层并恢复基础版本。

内置和导入基础层不会被原位改写。编辑基础条目时，程序建立“玩家修订层”遮罩原条目；即使玩家把修订层停用，旧事实也不会意外重新进入模型上下文。只有点击“恢复基础版本”才会撤销覆盖层。软删除保留资料和审计历史，之后仍可重新启用。

世界书适合保存统治者更替、地点毁坏、法律变化、组织状态等跨场景长期事实。人物眼下的情绪、所在位置和短期目标应保留在角色状态中。保存世界书不会调用 AI 模型，也不会创建新剧情回合；但会保护玩家修改，因此最新 AI 回合不能再直接重生成。

### 9.7 原文

支持导入最多 5 份 UTF-8 `.txt` 或 `.md` 文件。每份可以设置：

- 是否启用；
- 当前原作章节（可手动调整，也可随剧情推进自动解锁）；
- 是否阻止检索未来章节；
- 平衡参考或高度贴合。高度贴合会在活动剧本任务中额外使用下一章节的少量防剧透导演锚点，约束角色提出的重大方案和关键机制。

程序把原文保存在本机并建立切片。生成时只向当前模型供应商发送与本轮人物、地点、活动任务和输入相关的少量片段。普通引用不会越过当前进度；高度贴合模式可以读取紧邻的下一章节作为导演锚点，但只能在剧情自然抵达时保留原作的核心机制、必要参与者和条件，不能把后续事件写成已经发生的事实。回合详情只显示锚点数量，不展开正文以防剧透。导入、设置和删除会留下不含正文副本的本地恢复快照。删除采用软删除：资料不再参与检索，但正文、切片、历史回合引用和上下文快照仍保留；若尚未继续剧情且同一原文没有更新修改，可以到“修改记录”撤销删除。

**剧本推进引导**：当剧情与剧本大纲保持一致（未偏离）且原文开启防剧透时，程序还会从下一章节自动提取少量“大纲方向提示”注入剧情，引导新剧情继续沿剧本推进（人物、地点与事件线索）。它同样不是已发生事实、不是角色已知情报；剧情自然抵达时才按大纲推进，明显偏离时自动停止注入。进度已到最后一章或没有原文时不产生引导。

**进度自动推进**：当剧情实际发生的内容推进到原作的后续章节时，系统会自动把“当前原作章节”向后解锁（只进不退，最多解锁到该原文总章节数），防剧透的检索范围随之扩大；对话、日常等没有触及新章节的回合不会虚推进度。自动解锁会记录在“修改记录”中（“剧情推进自动解锁”），该记录只读、不可撤销，也不会阻止最新回合重新生成。玩家仍可随时在原文资料设置中手动调整进度。

### 9.8 记忆

长期记忆包含人物变化、事实、承诺、关系变化、未解决线索和章节摘要。

可以：

- 修改标题、正文和重要度；
- 固定一条记忆，使其优先召回；
- 标记线索已解决；
- 停用错误记忆；
- 设置记忆 token 预算、近期回合数和章节大小；
- 根据当前分支重新提取自动记忆。

手工修正的记忆不会被自动重建覆盖。记忆不能覆盖更晚回合或玩家当前输入。原文或记忆一旦在最新回合后被玩家修改，该回合便不能直接重生成；需要继续生成新回合，或从修改前的历史点建立分支。

### 9.8.1 游戏内时间模式

“游戏内时间模式”在**新建剧本时选择**（第一幕表单中的单选项；导入剧本包时按包声明预填，可修改），开局后确定、游戏中不可切换：

- **剧情驱动**（默认）：日期只随剧情推进变化（正文明确经过数小时、次日或数日后才推进），适合小说模式；
- **五回合一天**：每个回合固定推进一个时段（早上 → 上午 → 中午 → 下午 → 晚上），每 5 个回合进入下一天，适合跑团式剧本。

切换会保留当前游戏内日期，切换后从“早上”开始重新计时，不影响已经发生的剧情。五回合一天模式下，顶栏与历史回看会显示“第 N 日 · 时段”（如“第 2 日 · 中午”），任务期限与状态词条到期仍按天计算（一天 = 5 个回合）。

剧情中角色明确约定的未来时间点（如“三日后见面”“下周一交稿”）会被登记为约定，到期时在剧情中体现兑现或错过（详情见游戏内“本轮变化”与时间相关提示）。

### 9.9 修改记录与恢复

此栏目先列出玩家对原文和剧情记忆执行的修改，再列出剧情与管理操作造成的持久状态变化，包括：

- 角色当前状态和角色演化；
- 关系值；
- 地点；
- 世界书变化，包括玩家管理产生的覆盖层；
- 剧情走向和任务状态；
- 场景状态。

可以查看字段修改前后差异、变化原因和剧情证据。原文导入、设置、删除，以及记忆条目和记忆设置修改，在满足以下条件时显示“撤销这项修改”：

- 仍位于修改发生时的当前剧情节点，尚未继续生成新剧情；
- 它是同一原文或记忆对象的最新修订；
- 该动作尚未撤销并且包含恢复快照。

重建记忆索引、旧版只读记录、已被后续修改覆盖的动作不能自动撤销。撤销仍会留下新的记录，不会抹掉审计历史。

“撤销这项变化”不会删除历史对话，而是在当前分支头追加补偿记录，把该实体恢复到变化前状态。由于恢复的是完整实体，更晚的同实体修改可能被覆盖，操作前请阅读确认提示。

字段锁对同一剧本全部分支生效，只阻止 AI 自动改写，不限制玩家手工管理。被锁定拦截的模型修改会显示在对应回合的“本轮变化”中。

### 工作台与历史回合的关系

工作台修改当前活动分支的现行资料，不会改写过去回合。若需要从旧状态继续，应先从历史回合创建新分支，再在新分支中编辑。

## 十、历史回看、分支与存档

### 历史回看

右侧“回看剧情”可以读取任意历史回合。场景栏会同时显示该回合当时的游戏内日期（“游戏内第 N 日”）与回合序号。历史状态是只读的，不能把旧候选项直接提交到当前时间线。点击“返回最新回合”后才能继续游戏。

### 从历史创建分支

从任意历史回合创建分支时，程序会冻结该回合结束时的人物、地点、关系、世界书、任务和剧情走向。父分支之后的新变化不会串入子分支。

### 分支管理

可以：

- 切换活动分支；
- 修改分支名称；
- 把任意支线“设为主线”：新主线会吸收原主线及父链在分叉点之前的历史，成为一条历史完整的主线；原主线及其父链变为新主线的分支（分叉点之后各自推进的内容保留；没有推进过则成为空分支，可从分叉点继续发展新路线，不需要时也可以删除）。删除保护跟随新主线；
- 删除非主线分支（主线不能删除）。

AI 生成回合的过程中也可以随时切换分支或恢复存档：在途生成仍会保存在发起时的分支，界面会保持在切换后的分支，直接重新生成即可。若出现“本轮没有保存”提示，请先打开“分支与存档”确认当前活动分支，再重新提交。

### 手动存档和自动快照

手动存档保存当前回合以及该回合后发生的手工编辑状态。恢复点列表中的每个存档提供两种使用方式：

- **恢复为新分支**：以该存档为起点建立新分支并切换过去，原路线完整保留（适合想保留当前走向、只换一条路线试试的情况）；
- **恢复**：就地回到该存档点，删除这一分支中存档之后的推进内容，直接用存档时的状态继续（适合走错方向、想回到结局前重新选择的情况）。如果存档属于其他分支，程序会自动切换过去；如果存档之后已经分叉出子分支，恢复会被拒绝，此时应改用“恢复为新分支”以保护衍生路线。

程序在开局和每五个回合建立自动恢复快照，同样可以恢复或恢复为新分支。

### 结局后回到结局前

当剧情被判定滑向坏结局（`bad_end` 置位）时，正文上方的“结局警示”横幅会直接提供“打开分支与存档”按钮和最近的恢复点快捷入口：点击“回到结局前”即可恢复到结局之前的存档，重新选择路线；也可以打开分支与存档面板，从更早的历史回合或恢复点恢复、或建立新分支。恢复后结局警示会随状态一并清除。

## 十一、实际 AI 上下文

在 AI 回合的“本轮变化”中点击“查看实际上下文”。

可以核对：

- 生成模型与输入 token；
- 本地 token 估算；
- 请求次数和是否触发结构修复；
- 每个角色的角色卡、当前状态、原文和长期记忆是否进入本轮；
- 各上下文分区大小；
- 实际结构化故事资料；
- 系统消息和用户消息。

“人物依据诊断”只表示输入资料是否覆盖，不代表角色还原度百分比。若人物表现偏差，可以先检查：

1. 角色卡是否进入；
2. 当前状态是否进入；
3. 是否检索到该角色的原文片段；
4. 是否召回关键旧事；
5. 是否有资料因预算被裁剪。

旧版本产生的历史回合可能没有快照。系统不会事后伪造；重新生成或继续产生的新回合会正常记录。

## 十二、完整存档与整库备份

### 完整存档

用于迁移单个剧本，包含：

- 分支和全部回合；
- 人物、关系、地点、世界书和任务状态；
- 原文和切片；
- 长期记忆；
- 原文与记忆的内容动作审计；
- 状态审计、字段锁和回滚；
- 手动存档和自动快照；
- 重生成记录；
- AI 实际上下文快照。

当前完整存档版本为 `1.9.0`。它会保存资料恢复快照、原文软删除状态、伏笔/偏离触发器/属性判定的管理审计，以及主线身份标志。导入前会校验 SHA-256、内部引用和数据表；导入始终创建名称带“（导入）”的新副本，不覆盖原剧本。`1.8.0` 及更早旧存档仍可导入（旧档缺少主线标志时按根分支即主线恢复），其中已有的原文与记忆动作会作为不可撤销的只读历史显示。

导入入口位于“继续游戏”二级页面。左侧“整库备份与恢复”只管理整台电脑的 SQLite 备份，避免把单剧本迁移和整库回滚混在同一个入口。

### 整库备份

整库备份保存这台电脑上的全部剧本。程序会在启动、迁移和退出时自动建立备份，首页也可手工创建。

恢复整库前，程序会先建立一份 `pre-restore` 安全备份；恢复失败时使用安全副本回滚。

### 如何选择

| 需求 | 使用方式 |
| --- | --- |
| 分享一个尚未开始的故事 | 完整开局剧本包 |
| 迁移一个已经游玩的故事 | 完整运行存档 |
| 恢复这台电脑上全部故事 | 整库 SQLite 备份 |
| 只补充某个角色或世界设定 | 人物卡或世界书 JSON |
| 给现有故事补充小说依据 | 原文 TXT/Markdown |

## 十三、文件选择与隐私

### 哪些文件保存在本机

人物卡、世界书、剧本包、原文、剧情、记忆、存档、上下文快照和备份都保存在本机数据库或本地文件中。

桌面版内部数据都在软件同级 `用户数据/`。退出应用后删除整个外层 `AI酒馆` 文件夹即可卸载并清理程序主动建立的本机数据。通过导出或下载主动保存到其他目录的文件由玩家自行管理，不会随卸载删除。

### 哪些内容会发送给模型供应商

生成一回合时，程序发送：

- 系统规则；
- 当前必要的角色卡和状态；
- 相关世界书；
- 当前任务和剧情走向；
- 近期剧情与召回记忆；
- 少量相关原文片段；
- 玩家本轮输入。

程序不会把 SQLite 数据库、整库备份、完整运行存档或 API Key 放进提示词。

“AI 原文分析与生成”是玩家主动发起的例外流程：分析阶段和确认后的正式生成会分别发送一次，短文每次整份发送，长文每次只发送最多 48,000 字符的代表片段。普通人物卡、世界书和已有剧本包导入仍只在本机解析。

### 分享文件前

完整运行存档可能包含完整剧情、玩家输入和原文正文。分享前应自行确认其中是否包含不希望交给他人的内容。

## 十四、常见问题

### 1. 模型配置后仍显示未配置

先从主菜单进入“API 配置”，检查 Base URL、模型名称以及供应商是否要求密钥，再执行可用性审核。若手工编辑 `.env.local`，确认文件位于项目根目录、变量名正确，并重新启动开发服务器。

### 2. 生成失败后剧情会不会只保存一半

不会。模型请求、输出校验或数据库事务失败时，本轮不会提交部分剧情或部分状态。

### 3. 为什么角色和原作差异很大

先打开实际上下文，检查角色卡、原文片段和关键记忆是否进入。然后在人物栏目补充稳定性格、说话方式和对话示例，或调整原文进度与贴合度。

### 4. 为什么某角色没有出现在当前场景

检查人物是否启用、是否在场，以及当前地点的默认阵容。剧情也可以通过真实事件让角色加入或离场。

### 5. 为什么当前任务没有自动接续下一任务

检查前置任务、启用条件、自动接续开关和剧情连续性。如果剧情已经偏离预埋路线，系统会优先沿已发生事实生成新目标。

### 6. 原文会不会造成剧透

启用“阻止未来内容”，并把当前章节设置为实际进度。未来章节会在本地检索阶段被排除。

### 7. 工作台修改会不会改写过去剧情

不会。它修改当前活动分支后续使用的资料。过去回合仍保留原叙述和当时的上下文快照。

### 8. 怎样安全尝试另一条路线

从合适的历史回合建立新分支，或先建立手动存档再继续。不要通过直接修改数据库尝试回退。

### 9. 完整剧本包为什么不能直接作为运行存档恢复

剧本包只包含开局内容；运行存档还包含回合、分支、动态状态、记忆和审计记录，两者用途不同。

### 10. 旧回合为什么没有“实际上下文”

该功能上线前没有保存真实请求，程序不会事后猜测。新回合和成功重新生成的回合会保存。

### 11. 为什么模型出现在目录里，审核却失败

目录可能是公开的，也可能只表示套餐理论上暴露该模型；实际 token 仍可能没有权限、余额不足、被限流，或者模型使用当前酒馆尚未适配的协议。以“审核可用性”的最小生成结果为准。

### 12. 桌面版如何升级或彻底卸载

升级前退出程序并复制一份 `用户数据/`。保留原 `用户数据/`，只替换同级的 `AI酒馆.app`。当前开发版数据库迁移不保证旧版本回读，因此跨版本测试最稳妥的方式是先备份整个外层文件夹。彻底卸载时退出应用，再删除整个外层 `AI酒馆` 文件夹；玩家此前主动导出到其他位置的文件需要单独删除。

### 13. 为什么亲人或夫妻的信任度不是从 0 开始

剧本包可以声明开局初始关系（信任、好感、恐惧、敌意、敬意），系统会自动建立双向记录并物化到人物关系；未声明的角色之间仍保持中性（0）并标记“关系尚未建立”。如果导入后关系仍全部为 0，请确认剧本包包含 `initialRelationships` 分区，且角色姓名与人物卡一致。

### 14. 为什么地图上没有某些角色

地图只显示当前位置已知的人物。尚未登场、位置未知（如未记录所在地点）的角色不会出现在地图上；随剧情登场或移动到明确地点后会自动出现。

### 15. 为什么任务到期后剧情突然恶化

设有游戏内期限的任务（如三日内解毒、婚礼前完成安保）在剧情时间推进到期后，期限后果会作为导演级硬事实注入上下文，剧情必须让后果显现（中毒恶化、约期已过、反派抢先）。游戏内日期只随剧情中实际流逝的时间推进，纯对话回合不会让日期自动增加。想避免后果，需要在期限前让剧情完成对应任务或改变剧情条件。

### 16. 为什么 AI 生成了与上一回合几乎一样的内容

系统会检测与上一回合高度重复的场景并自动要求推进重写；若重写后仍重复，本轮会判定失败，不写入任何状态。此时可以换一种更具体的输入，或调整提示词里的“剧情走向”推动发展。

### 17. 生成时的进度条是什么意思

回合生成采用流式传输：进度条与“已生成 N 字”表示模型正在输出。完整内容只有通过结构、角色引用与状态校验后才会整体保存并显示，因此进度条完成前剧情不会落库。
