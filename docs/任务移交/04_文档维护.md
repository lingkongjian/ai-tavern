# 移交提示词：文档维护

> 用途：在新对话中启动"文档维护"工作流时，把本文件全部内容粘贴给新对话。
> 本进程只负责项目文档的编写、核对与同步，不修改产品代码。

## 项目背景

AI 酒馆（Next.js 16 + React 19 + SQLite + Electron 桌面封装），当前版本 0.1.16。公开仓库 `lingkongjian/ai-tavern`，文档随源码一起维护并推送（推送需用户确认）。

## 工作流铁律

1. 文档修改按"文案同步规范"执行：功能或行为变更时，README、docs 规范、操作手册、公开标准示例、Release 说明必须一并同步，不能只改一部分。
2. git 提交作者：`OpenCode Assistant <opencode@local>`；只本地提交，推送需用户确认（`git -c http.proxy=http://127.0.0.1:7890 push origin github-main:main`）。
3. 提交前跑 `node scripts/检查公开仓库.mjs`（测试资料目录、`发布/`、`.env.local`、数据库均被 gitignore 排除，不得意外提交）。
4. 版本号同步：`package.json`、README 顶部"当前版本"、`docs/release-说明-v<版本>.md` 三处必须一致。

## 文档风格约定

- 中文正文，规范词使用"必须/应该/可以"；技术术语保留英文（sceneTransition、storyModules 等）。
- 与代码实现保持逐字段一致：协议字段名、枚举值、实体类型、规则编号（系统消息规则 1~21，新增规则延续编号）。
- 失效说明必须删除或改写（例：0.1.11 后 DEEPSEEK.md"不使用流式输出"已改为流式进度反馈）。
