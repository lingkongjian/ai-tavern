# 移交提示词：发布与交付

> 用途：在新对话中启动"发布与交付"工作流时，把本文件全部内容粘贴给新对话。
> 本进程只负责 Git 推送、GitHub Release 发布与版本交付，不进行功能开发。

## 项目背景

AI 酒馆：本地优先的 AI 互动叙事工具（Next.js 16 + React 19 + SQLite + Electron 桌面封装）。公开仓库：`https://github.com/lingkongjian/ai-tavern.git`（远端 main 与本地 `github-main` 分支对应）。运行版位于 `/Applications/AI酒馆/`。

## 工作流铁律

1. **推送与发布必须先经用户明确确认**（用户原话："项目后续推送需要由我测试后再推送"）。本地提交完成后等待用户测试确认，用户说"推送"才执行推送与 Release。
2. git 提交作者固定：`OpenCode Assistant <opencode@local>`。
3. GitHub 推送必须走代理：`git -c http.proxy=http://127.0.0.1:7890 push origin github-main:main`（FlClash 代理，端口可能变化，用 `lsof -nP -iTCP -sTCP:LISTEN | grep -i flclash` 确认；只推 `github-main:main`，禁止 `--all`/`--mirror`）。
4. GitHub 凭据在 macOS 钥匙串（`github.com` / `lingkongjian`），无需再输入。
5. **完整交付原则**（用户要求）：推送时必须一并同步相关文案（README、docs、操作手册、公开标准示例）和最新版安装包（Release），不能只推送一部分。推送后到网页复查文件列表、README 渲染与 Release 附件。
6. 推送前必须跑 `node scripts/检查公开仓库.mjs`（public:check）确认无密钥/存档/测试资料混入；测试资料目录被 gitignore 排除。

## 发版流程（一条命令）

```bash
node scripts/发布GitHubRelease.mjs
```

脚本行为：验证桌面包敏感信息 → 创建/更新 tag v<版本> 的 Release → 上传 `AI-Tavern-<版本>-macOS-arm64.dmg/zip`（英文资产名，GitHub 不支持中文文件名）→ 读取说明文案。说明文案维护在 `docs/release-说明-v<版本>.md`（每版新建并更新 README 文档索引）。选项：`--dry-run` / `--skip-verify` / `--force-assets` / `--body-file <文件>`。

## 手动操作步骤（若脚本异常）

1. `git -c http.proxy=http://127.0.0.1:7890 push origin github-main:main`（先 `git log origin/main..HEAD --oneline` 核对待推内容）。
2. 发布 Release：用钥匙串 token（`security find-internet-password -s github.com -w`）调 GitHub API（POST `/repos/lingkongjian/ai-tavern/releases`，tag `v<版本>`，target `main`），再上传资产到 `uploads.github.com` 的 upload_url（`Content-Type: application/octet-stream`）。
3. 验证：GET release 检查资产列表、文件名、大小；网页复查。

## 常见坑

- 代理端口不是固定的（曾 7890 → 7000 → 7890），推送前先探测。
- 上传资产用英文名；中文名会被 GitHub 回退为 `default.txt`。
- 构建桌面包时若发布目录含运行数据会被拒绝：先 `rm -rf 发布/AI酒馆-<版本>-macOS-arm64`（该目录只有构建产物时才可删）。
- 版本号升级：`package.json` + README 顶部"当前版本" + `docs/release-说明-v<新版本>.md` 三处同步。

## 交付标准

- 推送后 `git log origin/main -1` 与本地 HEAD 一致；Release 页面资产完整；README/文档已同步。
- 告知用户 Release 链接与推送摘要。
