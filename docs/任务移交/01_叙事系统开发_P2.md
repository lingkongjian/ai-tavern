# 移交提示词：叙事系统开发（P2 增强）

> 用途：在新对话中启动"叙事系统 P2 增强"工作流时，把本文件全部内容粘贴给新对话。
> 本进程只负责 P2 三个核心功能的开发，不处理发布、文档或测试资料维护。

## 项目背景

AI 酒馆：本地优先、由玩家掌握角色控制权的 AI 互动叙事工具。技术栈：Next.js 16（`--webpack`，端口 3210）+ React 19 + TypeScript 5.9 + SQLite（node:sqlite）+ Drizzle 0.45 + Tailwind 4 + Electron 43 桌面封装（Apple Silicon）。当前版本 0.1.16，桌面版运行于 `/Applications/AI酒馆/AI酒馆.app`（用户数据在 `/Applications/AI酒馆/用户数据/`）。

## 工作流铁律

1. 改动完成后**只在本地提交到 `github-main` 分支，绝不推送、绝不发布 Release**；用户测试确认后才会另行安排推送。
2. git 提交作者固定为：`OpenCode Assistant <opencode@local>`（命令加 `-c user.name="OpenCode Assistant" -c user.email="opencode@local"`）。
3. 每次改动后必须：`tsc --noEmit` → `node --disable-warning=ExperimentalWarning --test tests/*.test.mjs`（当前 101/101 全过）→ ESLint（`node node_modules/eslint/bin/eslint.js . --ignore-pattern dist --ignore-pattern .next`）→ `node scripts/检查公开仓库.mjs`。
4. 桌面端验证：`rm -rf 发布/AI酒馆-<版本>-macOS-arm64 && node scripts/构建macOS桌面包.mjs`，然后退出运行版、替换 `/Applications/AI酒馆/AI酒馆.app`、重启并 curl 本地服务端口验证。
5. 功能或行为变更必须同步文档（README、操作手册 `public/使用手册/AI酒馆操作手册.md`、`docs/GENERATION_SPEC.md`、`docs/IMPORT_FORMAT.md`、`docs/STORAGE.md` 等）——这是"文案同步规范"的硬性要求。
6. Node 不在 PATH：用 `export PATH="$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin:$PATH"`。
7. 测试资料目录（`测试资料/`）被 `.gitignore` 排除，不进公开仓库。
8. 剧本包相关改动要同步更新 `public/文件标准/剧本包.schema.json` 与 `剧本包标准示例.json`。

## 已完成的叙事基础（0.1.12~0.1.16，勿重复实现）

- **防重复续写**：`lib/story/重复检测.ts`（n-gram Jaccard，阈值 0.55），回合与重生成校验阶段接入，命中触发推进修复；系统消息规则 20。
- **初始关系（双向）**：剧本包 `adventure.initialRelationships` 分区，开局物化自动建立正向+反向两条关系记录（`lib/storage/story-store.ts` startAdventure）；人物管理"角色关系"面板按角色对合并显示双向数值。
- **地点预注册**：剧本包 `adventure.locations` 分区（名称/描述/常驻角色/important），开局预注册 location 实体；与开场地点同名跳过。
- **离场角色位置**：`sceneTransition.offstageUpdates`（协议 1.1.0，`回合协议.ts`），不在场角色显式移动，自动创建新地点。
- **游戏内时间**：`session_state.core.gameTimeDay` 第 1 日开始，每回合默认 +1 天，`timeAdvance`（moment/hours/one_day/several_days）可覆盖；游戏页顶栏显示日期，历史回看显示当时日期。
- **任务期限**：storyModule `deadlineDay`，到期后 `expiredDeadlines` 作为导演级硬事实注入提示词（`剧情提示.ts` 规则 21）。
- **UI**：顶栏"人物/地点"直达按钮（人物管理+关系面板；地点管理列表含默认登场/当前在此）、"编辑剧本"=任务/世界书/原文/记忆、多 API 切换在顶栏左侧、新建页展示剧本包三区块（任务+期限/初始关系/地点）。
- **原文生成剧本包**：提示词已支持 initialRelationships（每对一条，自动双向）、locations（排除开场同名）、deadlineDay（无期限省略字段，解析兼容 0）。

## 本进程任务：P2 三个核心功能（按顺序实施）

### 1. 伏笔系统（plot_thread）
- 剧本包新增可选分区 `foreshadowing`：`{id, keywords, seedCondition, payoffCondition, payoffSummary, characters}`（工作台可编辑，原文生成阶段自动提取并本地校验必填字段）。
- 游戏内新状态实体 `plot_thread`（复用 `materialized_states`）：`seedCondition` 满足后激活，按相关度进入上下文（在 `剧情提示.ts` 的 rankedStates 权重中加高相关度）；`payoffCondition` 满足时注入"回收伏笔"导演提示。
- 解决"跨章节伏笔在短上下文下丢失真正目的"的问题，与现有 `upcomingScriptGuidance`（仅下一章节锚点）互补。

### 2. 偏离触发器（plot_trigger）
- 剧本包新增可选分区 `triggers`：`{id, when(条件描述), consequence(后果描述), stateEffects}` + 可选 `deadline`。
- 新状态实体 `plot_trigger`：条件满足时注入"意外阻碍"导演约束 + 强制状态变化（配偶怀疑度、反派敌意、bad_end 标志）。
- bad_end 标志置位后进入游戏页"结局警示"横幅。
- 示例场景：主角弱小时强闯反派地盘 → 强大反派提前登场；已婚状态下与异性接触 → 正主怀疑、敌我关系大幅转变。

### 3. 属性判定 + 骰子面板（玩家可见）
- 属性：`character_state.attributes`（力量/敏捷/感知/意志/魅力等，0-100，白名单校验）；事件驱动属性变化走现有 `characterStateChanges`。
- 判定协议：生成输出新增 `attributeChecks: [{characterId, attribute, difficulty, context}]`（模型只提议"何时判、用什么属性、多难"，不自行定结果）。
- **骰子面板流程（用户已确认方案）**：回合生成结果含判定请求时不立即落库 → 界面弹窗展示"属性 vs 难度 + 骰子"，玩家可掷骰/重掷/确认 → 后端 `lib/story/判定服务.ts`（新建）确定性结算：`d100 + 属性 vs 难度`，|属性−难度|≥30 直接判定（悬殊不掷骰），否则 30% 波动 → 结果作为已发生事实事件回填该回合（成功/失败/部分成功 + 状态影响），不重新生成叙述。
- 判定记录进入状态审计，可回看。
