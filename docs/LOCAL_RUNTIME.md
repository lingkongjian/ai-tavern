# 本地运行与 Windows/macOS 桌面封装

AI 酒馆只在玩家自己的电脑上运行，不依赖线上业务服务器。

## 开发阶段

Windows 用户安装 Node.js `>=22.13.0`（含 npm）后，可双击项目根目录的 [`启动AI酒馆.cmd`](../启动AI酒馆.cmd)。启动器检查端口占用、用 `npm ci` 安装缺少的依赖、创建配置并打开浏览器。关闭前按 `Ctrl+C` 停止服务。PowerShell、cmd 和 macOS 终端都可以使用 `npm run dev`、`npm run build`、`npm run start`。

macOS 用户可以在项目根目录双击 [`启动AI酒馆.command`](../启动AI酒馆.command)。启动器会：

1. 检查 Node.js 版本。
2. 首次运行时安装项目组件。
3. 在缺少 `.env.local` 时根据模板创建本地配置文件。
4. 只在本机 `127.0.0.1:3210` 启动开发服务。
5. 服务可用后自动打开默认浏览器。

开发阶段会保留一个终端窗口，用于显示运行状态。关闭该窗口或按 `Control-C` 会停止 AI 酒馆。

如果 `3210` 端口已被其他程序占用，启动器会停止并给出提示，不会连接或关闭其他程序。

## 模型供应商配置

源码开发版本通过项目根目录的 `.env.local` 保存模型配置。首次双击启动时，如果该文件不存在，启动器会根据 `.env.example` 自动创建。桌面版改为保存到软件文件夹中的 `用户数据/配置/模型.env`，不会读取或打包源码目录现有的 `.env.local`。两种模式都可以从游戏主菜单进入“API 配置”，选择供应商、读取模型目录、选择模型并执行可用性审核。

网页保存后立即对当前开发进程生效。也可以手工打开 `.env.local` 填写：

```dotenv
AI_PROVIDER=deepseek
AI_API_BASE_URL=https://api.deepseek.com
AI_API_KEY=在这里填写你的DeepSeek密钥
AI_MODEL=deepseek-v4-flash
AI_JSON_MODE=response_format
```

手工保存后需要停止并重新启动 AI 酒馆。密钥只在本地服务端读取；不要给变量名添加 `NEXT_PUBLIC_` 前缀，也不要把 `.env.local` 提交到 Git。旧文件没有 `AI_PROVIDER` 时会继续使用 DeepSeek。

通用云端接口必须填写供应商提供的 HTTPS Base URL、模型 ID 和 API Key。本地兼容接口允许使用 `http://127.0.0.1` 或 `http://localhost` 且密钥可以留空。若服务不支持 `response_format`，将 JSON 输出方式切换为“仅用提示词要求 JSON”。

LM Studio 使用 `http://127.0.0.1:1234/v1`，JSON 输出方式选择“JSON Schema（LM Studio）”（`AI_JSON_MODE=json_schema`）。此模式在审核与剧情流式请求中都发送根类型为 object 的 JSON Schema，具体剧情结构仍由酒馆校验。旧的 `response_format` 模式发送 `json_object`，部分 LM Studio 版本会以 HTTP 400 拒绝。错误提示现在保留 HTTP 状态码与已隐藏密钥的服务端错误信息。

本地回合生成的单次请求默认超时为 30 分钟，包含提示词处理与输出；云端默认 90 秒，显式调用超时（例如审核的 30 秒）保持优先。浏览器中断会通过 AbortSignal 传递到模型请求，取消后不切换备用模型、不提交回合；LM Studio 正在处理提示词时可能到下一个检查点才释放任务。备用配置会在请求前验证，缺少密钥等无效项直接跳过。

“读取模型”会请求 Base URL 对应的 `/models`，通常不产生生成 token；“审核可用性”还会对所选模型发送一次最多 64 token 的最小 JSON 请求。目录能显示模型不等于当前 token 一定有调用权限，是否能用于游戏以完整审核结果为准。OpenCode Go 预设会自动填写 `https://opencode.ai/zen/go/v1`，并标记当前酒馆尚未适配的 Messages 或 Responses 协议模型。

## 本地数据

源码开发模式的运行数据统一放入不参与 Git 版本控制的 `data/` 目录：

```text
data/
├── ai-tavern.sqlite
├── assets/
├── imports/
├── exports/
└── backups/
```

`backups/` 中保存启动、迁移、退出和玩家手动创建的 SQLite 一致性备份，默认保留最近 12 份。首页“完整存档与本地备份”可以查看最近备份并恢复；恢复前会自动创建一份操作前安全备份。单个剧本的迁移则使用首页“导出”生成的 JSON 完整存档。

开发阶段的 `.env.local`、本地数据库、导入内容和玩家剧情都不得提交到 Git。

桌面模式把所有由程序主动建立的持久文件放在 `.app`（macOS）或 `.exe`（Windows）同级的 `用户数据/`：

```text
AI酒馆/
├── AI酒馆.app
├── 安装与卸载说明.txt
└── 用户数据/
    ├── 数据/             # SQLite 与 backups/
    ├── 配置/             # 模型.env，权限为 0600
    ├── 浏览器数据/       # Electron 会话与缓存
    ├── 日志/             # 桌面端与本地服务日志
    ├── 崩溃报告/
    └── 临时文件/
```

模型供应商请求仍会把必要剧情资料发送到玩家选择的外部 API；“只存在软件文件夹内部”指本机持久存储位置，不表示离线生成。玩家主动在文件选择器中导出的存档或下载文件会保存到玩家选择的位置，不属于程序内部数据目录。

## Windows 桌面包

在 Windows 本机运行 `npm ci` 后执行 `npm run desktop:build:win`。x64 产物位于 `发布/AI酒馆-<版本>-Windows-x64/`，包括完整运行文件夹与 ZIP；用户不需要 Node.js。Windows ARM64 采用本机架构构建，尚未实机验证。

完整解压到个人可写目录，双击 `AI酒馆.exe`。不要从 ZIP 内启动、单独移动 EXE 或把运行目录放在 `Program Files`。EXE、DLL、`resources` 等组件和 `用户数据/` 必须一起保留。此开发包尚无 Authenticode 签名，Windows 可能提示未知发布者。

Windows 的模型配置文件继承父目录的 ACL，POSIX 的 `0600` 不等同于 Windows 访问控制；请把程序放在自己的用户目录中。程序不要求管理员权限，也不修改执行策略。

`npm run desktop:verify:win` 会复验未使用过的发布目录：检查敏感文件、用包内 Electron 启动空数据库 API、把程序复制到带中文与空格的临时路径后启动隐藏窗口，并检查退出按钮桥接、退出备份和后台服务停止。测试数据会清理，不会写入发布包；构建检测到发布目录已有玩家数据时会拒绝覆盖。

构建和验证的公共逻辑在 `scripts/desktop-build.mjs` 与 `scripts/desktop-verify.mjs`，macOS/Windows 命令各自保留平台入口。GitHub Actions 在两个系统上执行生产打包与测试，并上传 ZIP 构建附件。

## macOS 桌面包

当前已经实现 Apple Silicon（arm64）开发测试包：

- 双击应用图标即可启动。
- 不显示终端窗口。
- 不要求玩家安装 Node.js。
- 网页界面、Next.js 本地服务、SQLite 和模型供应商调用封装在桌面应用内。
- 模型 API Key 通过设置界面填写，以 `0600` 权限保存到同级 `用户数据/配置/模型.env`。为满足“卸载不留额外数据”，桌面版不使用会在系统目录留下项目条目的 macOS Keychain。
- 本地 Next.js 服务由 Electron 无界面后台进程承载，不会作为第二个 `exec` 应用出现在 Dock；退出主窗口时后台服务也会一并停止。
- Electron 的会话、缓存、日志和崩溃目录也重定向到同级 `用户数据/`。
- 本地服务只监听随机的 `127.0.0.1` 端口，退出应用时一并停止。
- 退出应用时自动关闭本地运行组件。

构建命令：

```bash
npm install
npm run desktop:build:mac
```

输出位于 `发布/AI酒馆-<版本>-macOS-<架构>/`，包含可直接检查的 `AI酒馆/` 文件夹、ZIP 和 DMG。构建会运行生产编译、临时签名、敏感文件扫描和空数据库 API 冒烟测试。单独复验已有产物可运行：

```bash
npm run desktop:verify:mac
```

安装时把 DMG 中的整个 `AI酒馆` 文件夹复制到 `/Applications` 或个人目录等可写位置。不要直接从只读 DMG 运行，也不要只复制 `.app`，否则程序会拒绝启动并提示数据目录不可写。卸载前退出程序，然后删除整个外层 `AI酒馆` 文件夹。

当前版本为临时签名的开发测试包。公开分发前仍需开发者证书签名、Apple notarization、正式图标、升级兼容测试和 Intel 架构产物。

## 桌面版升级与故障定位

Windows 升级：先退出旧版并备份 `用户数据/`，完整解压新版本到新文件夹，再把旧 `用户数据/` 复制过去；不要仅替换 EXE。Windows 与 macOS 之间可通过应用的完整存档导出/导入迁移剧情，API 配置另行设置。

升级时先退出旧版，并备份旧文件夹中的 `用户数据/`。保留原 `用户数据/`，只替换同级的 `AI酒馆.app`；新版本启动时会自动运行数据库迁移。若升级失败，可换回旧 `.app` 并使用首页备份恢复，但数据库已经执行新迁移时不保证旧版本能够读取，因此开发阶段建议先复制整个软件文件夹。

启动故障优先检查 `用户数据/日志/桌面端.log` 和 `用户数据/日志/本地服务.log`。删除整个软件文件夹即可清理这些诊断信息；日志不会进入安装包，也不会自动上传。

### thinking 模式的生成额度

模型设置可为每个 API 配置保存“单次输出上限（Token，含思考）”与“生成等待上限（秒）”。旧配置仍使用 6000 Token、本地 1800 秒／云端 90 秒。LM Studio 开启 thinking 时，可尝试 16384 Token 和 3600 秒；输入与输出总量需适合模型加载的上下文容量。按 8 Token/秒计算，生成 16384 Token 约需 34 分钟，另加提示词处理时间。

收到输出截断提示时，请调整额度或减少／关闭思考后重试；程序不会保存不完整回合，也不会因为截断自动改用备用模型。额度只提供生成空间，不能保证模型及时结束思考。可用性审核仍使用 64 Token、30 秒短时测试，开启长思考时可能无法通过。
